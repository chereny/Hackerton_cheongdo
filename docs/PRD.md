# 청도 디지털 생활도우미 — 제품 요구사항 문서

| 항목 | 내용 |
| --- | --- |
| 문서 상태 | MVP 제안 |
| 제품 유형 | 반응형 웹앱 |
| 대상 지역 | 경상북도 청도군 |
| 주요 사용자 | 스마트폰 사용이 익숙하지 않은 어르신 |
| 핵심 가치 | 생활에 필요한 디지털 과제를 직접 익히고, 막히면 동네 사람에게 도움을 요청한다 |

## 1. 제품 개요

**청도 디지털 생활도우미**는 청도 지역 어르신이 스마트폰으로 자주 하는 생활 과제를 쉬운 안내와 반복 연습으로 익히도록 돕는 서비스다. AI 생활 코치가 검수된 안내 자료를 바탕으로 단계별 설명을 제공하고, 해결되지 않은 질문은 동네별 학습모임의 이웃·봉사자에게 연결한다.

앱이 사용자의 기기에서 실제 메시지를 보내거나 예약·결제·인증을 대신하지 않는다. 사용자가 무엇을 하는지 이해하고 직접 완료하도록 돕는다.

### 해결하려는 문제

- 스마트폰 기능이나 온라인 생활 서비스 이용 중 막혔을 때, 적절한 도움을 구하기 어렵다.
- 한 번 설명을 들어도 다시 따라 하기 어렵고, 같은 질문을 반복하게 된다.
- 지역에서 서로 돕는 활동이 흩어져 있어 질문과 해결 경험이 이어지기 어렵다.

### 제품 목표

1. 어르신이 일상 디지털 과제를 스스로 연습하고 완료할 수 있게 한다.
2. AI 안내로 해결되지 않는 질문을 지역 학습모임과 연결한다.
3. 과제 완료와 도움 요청 해결을 기록해 디지털 학습 및 생산성 효과를 측정한다.
4. Copilot SDK와 Microsoft Agent Framework를 AI 코치의 핵심 실행 흐름에 활용한다.
5. 필요한 Azure 구성만 사용해 서비스를 실제 배포하고 운영 상태를 확인한다.

### 비목표

- 실제 스마트폰을 원격 조작하거나 메시지·예약·결제·인증을 대행하는 기능
- 금융·의료·법률 판단 또는 긴급 구조 서비스
- 전국 단위 공개 SNS, 실시간 1:1 채팅, 영상 통화
- 주민의 민감정보·정확한 위치·연락처를 수집하는 회원 디렉터리
- 검증되지 않은 AI 답변으로 공식 행정·교통 정보를 보장하는 것

## 2. 사용자와 권한

| 사용자 | 필요와 권한 |
| --- | --- |
| 어르신 학습자 | 과제 탐색·연습, AI 코치 질문, 동네 모임 질문 및 도움 요청, 답변 확인, 해결 표시 |
| 이웃·봉사자 | 가입한 모임의 질문에 답변, 도움 요청에 응답, 해결 방법 공유 |
| 모임 운영자 | 모임 게시물 관리, 부적절한 게시물 숨김, 신고 확인 및 처리 |

모임 내부 게시물은 해당 모임 구성원만 볼 수 있다. MVP 데모는 테스트 계정과 가상 모임·가상 게시물을 사용한다. 실제 파일럿 전에는 최소 수집 항목과 사용자 동의를 확정한다.

## 3. 핵심 사용자 여정

1. 사용자가 역할과 동네 학습모임을 선택해 홈에 들어온다.
2. 홈에서 “사진 보내기”, “버스 정보 찾기” 등 과제를 고른다.
3. 큰 글씨의 단계 안내를 따라 연습하거나 AI 코치에게 막힌 지점을 질문한다.
4. AI가 검수된 안내 자료를 이용해 한 번에 한 단계씩 답하고, 사용자가 각 단계를 확인한다.
5. 사용자가 완료를 표시하면 과제 기록이 남는다. 해결되지 않으면 안내 답변을 직접 확인한 뒤 동네 모임에 질문/도움 요청을 게시한다.
6. 봉사자나 이웃이 답변하고, 어르신이 해결 여부를 표시한다.
7. 운영자와 팀은 개인 식별이 아닌 집계 지표로 학습 및 도움 연결 상황을 확인한다.

## 4. MVP 기능 요구사항

우선순위: **Must**는 시연 가능한 MVP 필수, **Should**는 핵심 흐름을 해치지 않는 범위에서 포함, **Could**는 시간 여유가 있을 때만 고려한다.

### FR-01 — 쉬운 홈과 과제 찾기 (Must)

- 학습자는 과제 제목과 짧은 설명이 있는 카드에서 과제를 고를 수 있다.
- 콘텐츠는 청도 생활 맥락에 맞는 검수된 과제부터 제공한다.
- 홈에는 이어서 할 과제, 완료한 과제, 소속 학습모임과 새 답변/도움 요청 상태를 보여준다.

**수용 기준**

- 첫 화면에서 대표 과제를 선택해 2번 이내의 추가 동작으로 학습을 시작할 수 있다.
- 콘텐츠가 없거나 로딩/오류가 발생하면 다음에 할 수 있는 행동을 쉬운 문장으로 안내한다.

### FR-02 — 단계별 과제 학습 (Must)

- 각 과제는 짧고 순서가 분명한 단계로 구성한다.
- 사용자는 현재 단계와 전체 진행 상태를 확인하고, 이전 단계로 돌아가거나 완료를 표시할 수 있다.
- 학습 화면에서 글자 크기를 키울 수 있고, 음성 읽기는 지원 브라우저에서 선택적으로 사용할 수 있다.
- 실습은 모의 화면 또는 일반 설명을 사용하며 실제 계정 비밀번호, 인증번호, 결제 정보 입력을 요구하지 않는다.

**수용 기준**

- 키보드 또는 터치로 이전/다음/완료를 조작할 수 있고 현재 단계가 시각적으로 구분된다.
- 음성 기능을 사용할 수 없는 환경에서도 전체 안내를 텍스트로 읽을 수 있다.
- 완료 상태는 저장되어 다시 방문해도 확인된다.

### FR-03 — AI 생활 코치 (Must)

- 학습자는 자연어로 막힌 지점을 질문할 수 있다.
- AI는 질문이 모호하면 답하기 전에 짧게 확인 질문을 한다.
- AI는 검수된 생활 안내 자료를 검색하는 도구를 통해 답을 구성하고, 쉬운 한국어로 한 번에 한 단계씩 안내한다.
- 응답은 생성 중임을 보여주고 스트리밍으로 표시한다. 사용자는 응답 중단, 다시 질문, 사람에게 도움 요청을 선택할 수 있다.
- AI 답변임을 명확히 표시하고, 가능한 경우 참조한 안내 자료의 제목/출처를 함께 표시한다.
- AI는 메시지 발송, 예약, 결제 등 외부 행동을 수행하지 않는다. 답변이나 게시글을 커뮤니티에 자동 게시하지 않는다.
- 근거 자료가 없거나 확신이 낮으면 단정적인 안내를 피하고 동네 모임의 도움 요청을 권한다.

**수용 기준**

- Copilot SDK가 모델 연결과 스트리밍 응답을 제공하고 Microsoft Agent Framework가 질문 명확화, 안내 검색 도구 호출, 응답 구성의 에이전트 흐름을 담당한다.
- 최소 한 건의 정상 도구 호출이 실제 데모에서 확인된다.
- 근거 자료를 찾지 못하거나 모델/도구가 실패하면 빈 답을 성공처럼 보여주지 않고, 재시도 또는 사람에게 요청하는 선택지를 제공한다.
- 사용자는 답변을 검토한 뒤에만 커뮤니티 게시를 진행할 수 있다.
- 실제 개인정보·인증정보를 보내지 말라는 안내를 질문 입력 주변에 표시한다.

### FR-04 — 동네별 학습모임 커뮤니티 (Must)

- 사용자는 자신이 가입한 모임의 질문 목록을 보고 질문 또는 도움 요청을 작성할 수 있다.
- 게시물에는 제목, 질문 내용, 유형(질문/도움 요청), 생성 시각, 해결 상태를 표시한다.
- 모임 구성원은 답변을 작성하고, 질문 작성자는 답변을 확인한 후 해결 상태를 바꿀 수 있다.
- 사용자는 게시물을 신고할 수 있고, 운영자는 신고된 게시물을 확인해 숨김 처리할 수 있다.
- 공개 전국 게시판과 1:1 실시간 채팅은 MVP에 포함하지 않는다.

**수용 기준**

- 학습자 한 명이 도움 요청을 게시하고, 다른 모임 구성원이 답변하며, 학습자가 해결 완료로 바꾸는 흐름이 저장된 상태로 끝까지 동작한다.
- 소속되지 않은 사용자는 모임 내부 질문과 답변을 볼 수 없다.
- 신고 및 숨김 상태는 화면에 반영되고 운영자 외 사용자는 숨김 게시물을 볼 수 없다.
- 비어 있는 모임, 미해결 질문, 오류 상태 각각에서 적절한 안내를 표시한다.

### FR-05 — 지원자 및 운영자 화면 (Should)

- 지원자는 자신이 참여한 모임의 미해결 질문과 도움 요청을 우선 확인할 수 있다.
- 운영자는 모임 게시물과 신고를 확인하고 숨김 처리 결과를 볼 수 있다.
- 개인별 활동을 감시하거나 순위를 매기는 기능은 제공하지 않는다.

**수용 기준**

- 미해결 게시물과 신고 게시물을 완료/미완료 상태로 구분할 수 있다.
- 권한이 없는 사용자의 운영자 기능 접근은 거부되고 사용자에게 안내된다.

### FR-06 — 학습 기록과 효과 지표 (Must)

- 학습자는 본인의 과제별 진행 및 완료 상태를 확인한다.
- 팀은 개인을 식별할 수 없는 집계로 과제 시작·완료 수, 완료까지 걸린 시간, 도움 요청 수·해결률을 확인한다.
- 사용자 자신감은 짧은 선택형 자기평가로 측정할 수 있으며, 응답은 서비스 개선 목적의 집계에만 사용한다.

**수용 기준**

- 대시보드는 정의된 분모·분자가 있는 지표를 표시한다. 예: 과제 완료율 = 완료한 과제 수 / 시작한 과제 수.
- 실제 파일럿 결과가 없을 경우 수치를 성과인 것처럼 표시하지 않고, 데모용 가상 데이터임을 명시한다.
- 집계 화면에는 이름, 연락처, 게시물 본문 등 개인 식별 정보가 노출되지 않는다.

## 5. AI 및 시스템 설계 요구사항

### AI 처리 흐름

1. 입력에서 비밀번호·인증번호 등 민감한 정보를 보내지 말라는 안내를 제공한다.
2. Agent Framework가 질문이 충분히 구체적인지 판단하고, 필요하면 확인 질문을 한다.
3. 생활 안내 검색 도구는 팀이 검수한 문서만 조회한다.
4. 에이전트는 검색 근거에 기반해 짧은 단계별 답변과 참조 자료를 생성한다.
5. 응답을 AI 생성 결과로 표시하고, 사용자가 직접 따라 해 보거나 사람의 도움을 요청하도록 한다.

검색된 안내 문서와 사용자 입력은 지시문이 아니라 데이터로 취급한다. 안내 자료 외의 임의 지시가 에이전트 동작을 바꾸지 않도록 도구와 시스템 지시를 제한한다. 모델 출력은 신뢰할 수 없는 입력으로 간주하며, 다른 사용자에게 게시하거나 외부 행동에 쓰기 전에 사용자 확인을 요구한다.

### Azure 통합

- 웹앱/API를 Azure 환경에 실제 배포하고 팀원이 따라 할 수 있는 배포 절차를 제공한다.
- 사용자·모임·질문·학습 기록을 저장할 영속 저장소를 사용한다.
- 애플리케이션 오류와 요청 상태를 확인할 수 있도록 Application Insights 또는 이에 준하는 Azure 관찰 기능을 연결한다.
- 비밀 값과 연결 문자열은 코드 저장소에 넣지 않고 배포 환경의 안전한 설정으로 관리한다.
- Azure AI 또는 특정 모델 서비스를 추가해야 한다고 전제하지 않는다. 실제 아키텍처와 모델 연결 방식은 선택한 SDK 구성에 맞춘다.
- 시연에 필요하지 않은 Azure 서비스를 형식적으로 늘리지 않는다.

## 6. 비기능 요구사항

### 접근성 및 사용성

- 모바일 화면과 데스크톱 화면에서 반응형으로 동작한다.
- 기본 문장은 쉬운 한국어를 사용하고, 한 화면에 한 가지 핵심 행동을 둔다.
- 읽을 수 있는 글자 크기, 충분한 색 대비, 큰 터치 영역, 명확한 포커스 표시, 키보드 조작을 지원한다.
- 색상만으로 상태를 전달하지 않으며, 오류는 무엇이 잘못됐고 어떻게 다시 시도할지 설명한다.
- 음성 읽기가 지원되지 않는 기기에서도 동등한 텍스트 흐름을 제공한다.

### 개인정보 및 보안

- MVP는 데모용 가상 사용자와 가상 데이터를 우선 사용한다.
- 운영/파일럿에서 필요한 데이터만 수집하고 수집 목적과 보관 기간을 알린다.
- 비밀번호, 인증번호, 금융 정보, 건강정보 및 불필요한 정확한 위치는 입력·저장하지 않는다.
- 모임 접근 권한을 서버에서 확인하고, 사용자가 보낸 콘텐츠를 화면에 안전하게 표시한다.
- 오류 로그와 AI 관찰 기록에 사용자 질문 원문이나 민감정보를 불필요하게 남기지 않는다.
- 커뮤니티 신고를 운영자가 검토할 수 있도록 하고, AI 생성 내용과 사람 답변을 구분해 표시한다.

### 신뢰성

- 네트워크·모델·검색 도구 오류에 대한 로딩, 재시도, 중단, 사람 도움 요청 경로를 제공한다.
- AI의 출처가 없거나 검색 근거가 없는 경우 사실로 단정하지 않는다.
- 사용자가 직접 게시와 해결 상태 변경을 확인하며, 되돌리기 어려운 외부 행동은 수행하지 않는다.

## 7. 성공 지표와 검증 방법

| 지표 | 정의 | 검증 |
| --- | --- | --- |
| 과제 완료율 | 완료 처리한 과제 수 / 시작한 과제 수 | 시연 및 파일럿에서 과제 시작·완료 기록 비교 |
| 완료 소요 시간 | 과제 시작부터 완료까지 걸린 시간의 중앙값 | 같은 과제를 도움 전후에 수행하도록 하고 시간 기록 |
| 도움 요청 해결률 | 해결 완료된 도움 요청 수 / 전체 도움 요청 수 | 모임 게시물의 해결 상태 집계 |
| 사용자 자신감 변화 | 과제 수행 전후 자기평가 점수 차이 | 짧은 동일 문항으로 전후 측정 |
| 도움 연결성 | 사람에게 도움을 요청한 사용자가 답변을 받은 비율 | 질문/도움 요청의 답변 상태 집계 |

실제 어르신 파일럿을 진행할 수 있다면 동의를 받은 소규모 사용성 테스트에서 과제별 기준선을 기록한다. 참가자를 확보하지 못하면 정량적인 효과를 주장하지 않고, 가상 데이터를 명시한 기능 시연과 측정 계획만 제시한다.

## 8. 데모 시나리오

1. 어르신 역할의 가상 사용자가 “손녀에게 사진을 보내고 싶어요”라고 AI 코치에 질문한다.
2. 코치는 필요한 앱/상황을 확인하고, 검수된 자료를 호출해 쉬운 단계로 스트리밍 안내한다.
3. 사용자는 안내를 따라 각 단계를 확인하고, 과제 완료를 표시한다.
4. 막힌 단계가 있으면 답변을 그대로 자동 게시하지 않고, 사용자가 확인한 뒤 동네 학습모임에 도움 요청을 올린다.
5. 봉사자 역할이 답변하고 어르신 역할이 해결 완료로 표시한다.
6. 집계 화면에서 과제 완료와 도움 요청 해결 지표를 확인한다. 파일럿 실측 전이면 데모 수치임을 표시한다.

## 9. 출시 완료 정의

- 주요 경로(과제 학습 → AI 안내 또는 사람 도움 요청 → 해결/완료 기록)가 처음부터 끝까지 동작한다.
- Copilot SDK 스트리밍과 Agent Framework 도구 호출을 실제 실행 화면에서 확인할 수 있다.
- 정상 응답, 근거 없음, 모델/도구 오류, 네트워크 오류에 대한 UI 상태가 구현되어 있다.
- 커뮤니티 권한 검사, 신고·숨김, 해결 상태가 정상 동작한다.
- 모바일/데스크톱 레이아웃과 핵심 접근성 항목을 점검했다.
- Azure 배포 및 로그 확인 절차를 다른 팀원이 재현할 수 있다.
- 문서, 시연 자료, 가상 데이터가 실제 파일럿 성과와 혼동되지 않게 구분된다.

## 10. 3인 역할 분담

역할은 주 담당자를 정해 병렬 작업이 가능하도록 나눈다. 각 담당은 자신의 기능을 끝까지 책임지고, API 계약과 데모 흐름은 첫 구현 전에 셋이 함께 합의한다.

| 담당 | 주 책임 | 주요 산출물 | 완료 기준 |
| --- | --- | --- | --- |
| **1 — 제품·UX·프론트엔드** | 사용자 흐름, 쉬운 문구, 접근성 디자인, 홈/과제 학습/AI 코치/커뮤니티 화면 | 화면 흐름·컴포넌트, 과제 콘텐츠 UI, 반응형 주요 화면, 로딩·빈 상태·오류 상태 | 어르신 주요 흐름을 모바일에서 큰 글씨·큰 조작 영역으로 끝까지 수행 가능하고 키보드/대비를 점검 |
| **2 — 백엔드·커뮤니티** | 사용자/모임/게시물/학습 상태 데이터, API, 권한, 신고·숨김, 지표 집계 | 데이터 모델과 API 계약, 모임 Q&A/도움 요청 API, 운영자 처리, 집계 API | 질문 등록→답변→해결, 소속 권한, 신고·숨김이 영속 저장 상태로 정상 작동 |
| **3 — AI 에이전트·Azure·통합** | Copilot SDK 및 Microsoft Agent Framework 흐름, 검수 안내 검색 도구, 스트리밍/실패 처리, Azure 배포·관찰성 | 코치 서비스, 안내 자료와 검색 도구, 배포 설정/절차, 운영 로그 | 출처가 있는 AI 답변과 불확실/오류 대체 경로를 시연하고 Azure 배포 및 로그 조회를 재현 |

### 공동 작업과 인터페이스

- **첫 공동 결정:** 화면-API 데이터 형식, 역할/권한, 데모용 가상 계정, AI 요청·응답 형식, 기본 배포 환경을 합의한다.
- **담당 1 ↔ 담당 2:** 화면이 사용할 API 계약과 오류 응답 형태를 조기에 고정한다. 프론트엔드는 계약에 맞춰 작업하고 백엔드는 예시 응답을 제공한다.
- **담당 1 ↔ 담당 3:** AI 응답 스트리밍, 출처 표시, 취소·재시도 UI 계약을 합의한다.
- **담당 2 ↔ 담당 3:** AI 질문을 커뮤니티 게시물로 저장할 때는 사용자가 게시를 확인한 뒤 백엔드 API를 호출하도록 한다. 에이전트에 게시/외부 행동 권한을 주지 않는다.
- **모두:** 매 통합 시점에 데모 시나리오를 실행하고, 접근성·개인정보·오류 동작을 함께 검토한다. 마지막에는 테스트와 시연을 함께 리허설한다.

역할은 팀원 숙련도에 따라 바꿀 수 있다. 다만 Copilot SDK와 Microsoft Agent Framework의 실제 사용, 커뮤니티 데이터/권한 소유자, Azure 배포 책임자는 초기에 각각 한 명씩 분명히 지정한다.
